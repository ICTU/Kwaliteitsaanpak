## Terminologie en afkortingen

De onderstaande tabellen bevatten afkortingen en termen die voorkomen in de $KWALITEITSAANPAK$ en bijbehorende templates.

### Afkortingen

| Afkorting | Betekenis | Toelichting |
|:----------|:----------|:------------|
| **API** | application programming interface | een vastgelegde interface waarmee **software** functionaliteit of gegevens beschikbaar stelt aan andere software |
| **ART** | automatische **regressietest** | **regressietest** die geautomatiseerd wordt uitgevoerd, bijvoorbeeld bij elke wijziging in de continuous delivery pipeline |
| **BIA** | businessimpactanalyse | $BIA$ |
| **BIO** | Baseline Informatiebeveiliging Overheid | het gemeenschappelijke normenkader voor informatiebeveiliging van alle overheidslagen, gebaseerd op NEN-ISO/IEC 27001 en 27002 |
| **DoD** | definition of done | de door het **scrumteam** vastgestelde criteria waaraan een user story moet voldoen om als gereed te gelden, waaronder het voldoen aan de kwaliteitsnormen |
| **DoR** | definition of ready | de door het **scrumteam** vastgestelde criteria waaraan een user story moet voldoen voordat deze in een sprint kan worden opgepakt |
| **DPIA** | data protection impact assessment | $DPIA$ |
| **FG** | functionaris voor gegevensbescherming | zie **functionaris voor gegevensbescherming** in de tabel met termen |
| **GFO** | globaal functioneel ontwerp | $GFO$ |
| **IAMA** | impact assessment mensenrechten en algoritmes | $IAMA$ |
| **IB-plan** | informatiebeveiligingsplan | $IB$ |
| **IPO** | intern projectoverleg | het periodieke projectoverleg van een ICTU-**project**, waarin onder meer de risico's en de uitvoering van de mitigerende maatregelen worden bewaakt (zie maatregel M10) |
| **ISD** | ICTU Software Diensten | afdeling van ICTU die **softwareontwikkelprojecten** ondersteunt met ontwikkel- en testomgevingen, tools en diensten |
| **ISE** | ICTU Software Expertise | afdeling van ICTU die **softwareontwikkelprojecten** ondersteunt met expertise op het gebied van **softwareontwikkeling** en die de $KWALITEITSAANPAK$ onderhoudt |
| **ISO** | International Organization for Standardization | zie **International Organization for Standardization** in de tabel met termen; ISO wordt ook gebruikt als afkorting van **Information Security Officer** |
| **KPI** | key performance indicator | meetbare grootheid waarmee wordt vastgesteld in hoeverre een doel wordt bereikt |
| **MTP** | mastertestplan | $MTP$ |
| **MVP** | minimum viable product | zie **minimum viable product** in de tabel met termen |
| **NFE** | niet-functionele eisen | $NFE$ |
| **NORA** | Nederlandse Overheidsreferentie-architectuur | het referentiekader voor de inrichting van de informatievoorziening van de Nederlandse overheid, met onder meer architectuurprincipes en -modellen |
| **NPR** | Nederlandse Praktijkrichtlijn | door NEN uitgegeven richtlijn die aanbevelingen geeft in plaats van eisen te stellen |
| **OGON** | OpdrachtGevers-/OpdrachtNemersoverleg | overleg tussen de **opdrachtgever** en ICTU als opdrachtnemer |
| **OTAP** | ontwikkel, test, acceptatie, productie | gebruikt om verschillende soorten omgevingen aan te duiden |
| **PKI** | public key infrastructure | het geheel van afspraken, organisaties en technische voorzieningen voor het uitgeven en beheren van digitale certificaten, waarmee de identiteit van partijen wordt vastgesteld en communicatie wordt beveiligd |
| **PRA** | productrisicoanalyse | $PRA$ |
| **PSA** | projectstartarchitectuur | $PSA$ |
| **PvA** | plan van aanpak | document waarin de aanpak, planning, benodigde middelen, risico’s en randvoorwaarden voor de uitvoering van een project of projectfase worden vastgelegd |
| **PvE** | programma van eisen | document waarin de opdrachtgevende organisatie de eisen vastlegt waaraan het op te leveren product moet voldoen |
| **SAD** | softwarearchitectuurdocument | $SAD$ |
| **SDM** | software delivery manager | zie **software delivery manager** in de tabel met termen |
| **TVA** | threat and vulnerability assessment | $TVA$ |
| **UX** | user experience | de ervaring van een gebruiker bij het gebruik van een product of dienst; zie ook **gebruikskwaliteit** en **usability** |
| **VIR** | Voorschrift Informatiebeveiliging Rijksdienst | voorschrift met regels voor de informatiebeveiliging binnen de rijksdienst |
| **VIRBI** | Voorschrift Informatiebeveiliging Rijksdienst Bijzondere Informatie | voorschrift met aanvullende regels voor de beveiliging van bijzondere (gerubriceerde) informatie binnen de rijksdienst |
| **VM** | virtual machine | virtuele machine: een softwarematige nabootsing van een computer, waarop een eigen besturingssysteem en eigen **software** draaien |

### Termen

| Term | Toelichting |
|:-----|:------------|
| **actor**      | een persoon die, of een extern informatiesysteem dat, een handeling verricht op het **informatiesysteem** |
| **architectuur** | een beschrijving van de structuur van een systeem, inclusief onderdelen, relaties tussen die onderdelen en eigenschappen van die onderdelen en relaties |
| **auditing** | vastlegging van de door een actor verrichte handelingen |
| **authenticatie** | het vaststellen van de identiteit van een **actor** |
| **autorisatie** | aan een **actor** toegekende rechten |
| **beheerorganisatie** | een (samenwerkingsverband van) organisatie(s) die in opdracht van een opdrachtgevende organisatie het **operationeel beheer**, applicatief beheer en/of functioneel beheer van **software** uitvoert |
| **broncode** | **software** in een vorm die leesbaar is voor mensen en de intentie van een programmeur uitdrukt |
| **deployment** | installatie van **software** op een systeem, waardoor de software beschikbaar wordt gemaakt voor gebruik door **actoren** |
| **developers** | Developers zijn de mensen in het **scrumteam** die iedere sprint gecommitteerd zijn aan het maken van elk aspect van een bruikbaar increment [Scrumgids] |
| **DevOps** | een praktijk die tot doel heeft **softwareontwikkeling** en **operationeel beheer** samen te brengen |
| **due diligence** | $DD$ |
| **functionaris voor gegevensbescherming** | onafhankelijke functionaris die binnen een organisatie adviseert over de bescherming van persoonsgegevens en toezicht houdt op de naleving van de privacywetgeving |
| **gebruikskwaliteit** | mate waarin een systeem, product of dienst kan worden gebruikt door gespecificeerde gebruikers, voor het bereiken van gespecificeerde doelen, met effectiviteit, efficiëntie en tevredenheid in een gespecificeerde gebruikscontext |
| **governance** | het geheel van afspraken over besluitvorming, verantwoordelijkheden, bevoegdheden en toezicht binnen een organisatie of project |
| **informatiesysteem** | een samenhangend geheel van gegevensverzamelingen en de daarbij behorende personen, procedures, processen en **programmatuur**, alsmede de voor het informatiesysteem getroffen voorzieningen voor opslag, verwerking en communicatie [VIR 2007, NORA] |
| **Information Security Officer** | functionaris die op organisatieniveau adviseert over informatiebeveiliging, bijdraagt aan de ontwikkeling en toepassing van informatiebeveiligingsbeleid en de beheersing van informatiebeveiligingsrisico’s, en toeziet op de naleving van beveiligingskaders en -maatregelen |
| **infrastructuurarchitectuur** | $IA$ |
| **interactieontwerp** | $IO$ |
| **International Organization for Standardization** | onafhankelijke, internationale organisatie die via samenwerking tussen nationale normalisatie-instituten internationale normen ontwikkelt en publiceert |
| **Jira** | tool om **use cases**, user stories, logische testgevallen en issues vast te leggen |
| **klantreis** | alle directe en indirecte interactie van een klant of gebruiker met een product of dienst |
| **Kwaliteitsaanpak** | de $KWALITEITSAANPAK$ is een set maatregelen gebaseerd op de risico’s bij de ontwikkeling van maatwerksoftware |
| **kwaliteitsmanager** | ondersteunt en coacht het scrumteam bij de kwaliteitszorg en het leveren van software van goede kwaliteit, monitort de softwarekwaliteit, signaleert kwaliteitsrisico’s en technische schuld, adviseert over verbeteringen en rapporteert aan de **projectleider** |
| **minimum viable product** | $MVP$ |
| **ontwikkelaars** | Ontwikkelaars (*developers* in de Scrumgids) zijn de mensen in het **scrumteam** die iedere sprint gecommitteerd zijn aan het maken van elk aspect van een bruikbaar increment [Scrumgids] |
| **opdrachtgever** | medewerker van de opdrachtgevende organisatie die eindverantwoordelijk is voor de opdracht aan ICTU |
| **operationeel beheer** | activiteiten die zorgen dat software operationeel is en blijft, zoals het oplossen van incidenten, het uitvoeren van onderhoud, het implementeren van upgrades en patches, het beheren van configuraties, en het monitoren van prestaties en beschikbaarheid |
| **persona** | een min of meer realistische beschrijving van een fictief persoon, veelal met naam, persoonskenmerken, drijfveren en behoeften, die een groep gebruikers representeert en gebruikt wordt om te redeneren over de gewenste functionele en niet-functionele eigenschappen van de **software** |
| **productbacklog** | De productbacklog is een levende, geordende lijst van wat nodig is om het product te verbeteren. Het is de enige bron van het werk dat door het **scrumteam** gedaan wordt [Scrumgids] |
| **productowner** | De productowner is verantwoordelijk voor het maximaliseren van de waarde van het product, dat het resultaat is van het werk van het **scrumteam** [Scrumgids] |
| **programmatuur** | zie **software** |
| **project** | een tijdelijke organisatie voor het realiseren van een resultaat - bij ICTU bestaat een **softwareontwikkelproject** uit medewerkers van ICTU, de opdrachtgevende organisatie, beheerorganisatie en eventueel andere partijen |
| **projectleider** | medewerker eindverantwoordelijk voor het projectresultaat - bij ICTU-softwareontwikkelprojecten is de projectleider een medewerker van ICTU |
| **projectsecretaris** | medewerker die de projectleider ondersteunt bij administratieve, organisatorische en financiële werkzaamheden binnen een project. Een projectsecretaris is werkzaam voor de afdeling Project- en Managementondersteuning (PMO). |
| **Quality-time** | een door ICTU ontwikkeld, open source, geautomatiseerd kwaliteitssysteem |
| **realisatiefase** | fase van een **softwareontwikkelproject** waarin de **software** daadwerkelijk wordt gebouwd en onderhouden, en bij een **DevOps**-werkwijze ook operationeel wordt beheerd |
| **regressietest** | test die na een wijziging controleert of niet-gewijzigde delen van een systeem nog steeds correct functioneren |
| **release** | een voor gebruik vrijgegeven versie van de **software** |
| **release notes** | een overzicht van de wijzigingen in een **release** |
| **Scrum** | Scrum is een lichtgewicht raamwerk dat mensen, teams en organisaties helpt om waarde te creёren door middel van adaptieve oplossingen voor complexe problemen [Scrumgids] |
| **scrummaster** | De scrummaster is verantwoordelijk voor het opzetten van **Scrum**, zoals staat beschreven in de Scrumgids [Scrumgids] |
| **scrumteam** | Een scrumteam bestaat uit één **scrummaster**, één **productowner** en **ontwikkelaars** (*developers* in de Scrumgids) [Scrumgids] |
| **securityadviseur** | adviseert over de informatiebeveiliging van softwareontwikkelprojecten, de ontwikkelde software en de bijbehorende ontwikkel- en bedrijfsprocessen en werkt hierbij samen met de kwaliteitsmanager, SDM, projectleider en productowner |
| **software** | software is de verzameling instructies die bepalen wat een computer uitvoert en is uiteindelijk wat de gebruiker ziet, ervaart en waarmee hij interacteert |
| **softwarearchitectuur** | een **architectuur** die vooral de softwareonderdelen en -relaties (processen, modules, interfaces, datamodel) van een systeem beschrijft |
| **software delivery manager** | organiseert het ontwikkelen en opleveren van **software** conform de vastgestelde eisen en de Kwaliteitsaanpak en rapporteert aan de **projectleider** |
| **softwareontwikkeling** | een activiteit die nieuwe **software** maakt en/of bestaande software aanpast |
| **softwareontwikkelproject** | een **project** dat de oplevering van **software** als enig of voornaamste projectresultaat heeft |
| **solution architectuur** | beschrijving van de gewenste oplossing van een specifiek probleem, of het eindresultaat van een **project** [NORA] |
| **technische schuld** | eigenschappen van de **software** die de inzetbaarheid en onderhoudbaarheid op lange termijn bedreigen |
| **usability** | gebruiksvriendelijkheid |
| **use case** | een afgebakende eenheid van interactie tussen een **actor** en het systeem |
| **voorfase** | fase van een **softwareontwikkelproject**, voorafgaande aan de **realisatiefase**, waarin de uitgangspunten, risico’s en randvoorwaarden voor de realisatiefase worden bepaald en waarin wordt gezorgd dat aan de randvoorwaarden wordt voldaan en dat voor zoveel mogelijk risico’s maatregelen getroffen zijn |
| **vrijgaveadvies** | advies om een **release** vrij te geven voor ingebruikname, met een testverslag dat ten minste alle nog openstaande testbevindingen en geconstateerde beveiligingsbevindingen bevat |
